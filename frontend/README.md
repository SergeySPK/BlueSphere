# Blue Sphere — Frontend

Frontend приложения **Blue Sphere** — Flutter Mini App для MAX WebApp.

Приложение предназначено для учеников, учителей и администраторов школы. Оно отображает классы, расписание, учебную нагрузку, тепловую карту и агрегированные результаты опросов.

Для учителей и администраторов дополнительно доступны выбор класса и AI-рекомендации.

## 3. Точка входа и навигация

### `lib/main.dart`

Основной файл приложения.

Содержит:
- инициализацию Flutter;
- корневой виджет `MyApp`;
- тему приложения;
- инициализацию адаптивной вёрстки Vize;
- `AuthWrapper` для авторизации через MAX;
- `MainScreen` для основной навигации;
- определение доступных вкладок в зависимости от ролей;
- преобразование технического кода класса в русское название.

### Последовательность запуска

1. Flutter инициализирует приложение.
2. `AuthWrapper` создаёт `MaxWebApp`.
3. Вызывает `webApp.init()`.
4. Получает `initData`.
5. Передаёт `initData` в `ApiService.auth()`.
6. Backend возвращает роли и доступные классы.
7. Приложение отображает основной интерфейс.

Если `initData` отсутствует, приложение записывает ошибку авторизации в лог. Запуск обычной страницы вне MAX не эквивалентен авторизации через MAX Mini App.

### Ролевая навигация

Для ученика:
- доступна вкладка нагрузки;
- класс выбирается автоматически из данных авторизации;
- доступна вкладка опросов;
- вкладка выбора классов учителя не отображается.

Для учителя и администратора:
- доступна вкладка классов;
- пользователь выбирает класс;
- выбранный класс передаётся в экран нагрузки и опросов;
- доступны функции, предусмотренные backend для соответствующей роли.

Ролевая проверка интерфейса не заменяет серверную проверку доступа.

## 4. Экраны приложения

### 4.1. `splash_screen.dart`

Экран загрузки.

Отображает:
- логотип;
- название приложения;
- индикатор загрузки;
- сменяющиеся информационные фразы.

Используется на этапе получения данных авторизации.

### 4.2. `classes_screen.dart`

Экран выбора класса.

Предназначен для учителей и администраторов.

Основные задачи:
- загрузка классов через API;
- отображение классов по параллелям;
- выбор нужного класса;
- передача выбранного класса в основную навигацию.

### 4.3. `load_screen.dart`

Экран учебной нагрузки.

Отображает:
- календарь;
- тепловую карту нагрузки;
- сводный статус выбранного дня;
- рекомендации;
- переход к подробному расписанию.

Получает данные через `ApiService` и использует доменные модели нагрузки и рекомендаций.

### 4.4. `day_details_screen.dart`

Экран подробной информации за выбранный день.

Отображает расписание занятий и связанную с ними информацию.

Для пользователей с соответствующими правами предусмотрено взаимодействие с редактированием занятий через backend.

Редактирование использует серверные сессии, поэтому frontend должен корректно обрабатывать ошибки доступа и занятости сессии.

### 4.5. `surveys_screen.dart`

Экран результатов опросов.

Основные задачи:
- получение доступных дат опросов;
- выбор даты;
- получение статистики;
- отображение агрегированных результатов.

Экран не должен раскрывать индивидуальные ответы учеников. Состав и доступность статистики определяются backend.

## 7. REST API и авторизация

### `lib/data/api_service.dart`

Централизованный HTTP-клиент приложения.

Использует пакет `http`.

Текущий базовый URL:

```dart
static const String baseUrl = 'https://blue-sphere-bot.bothost.tech';
```

Токен авторизации и выбранная школа хранятся в статических полях `ApiService`.

### Методы API

| Метод | Назначение |
|---|---|
| `auth()` | Авторизация через MAX `initData` |
| `getClasses()` | Получение классов школы |
| `getHeatmap()` | Получение тепловой карты за месяц |
| `getSummary()` | Получение статуса нагрузки на дату |
| `getRecommendations()` | Получение AI-рекомендаций |
| `getSchedule()` | Получение расписания на день |
| `updateLesson()` | Изменение занятия |
| `startEditing()` | Начало сессии редактирования |
| `renewEditing()` | Продление сессии редактирования |
| `stopEditing()` | Завершение сессии редактирования |
| `getClassSurveys()` | Получение дат опросов |
| `getSurveyStatistics()` | Получение статистики опроса |

### Авторизация

При успешном вызове `auth()`:
- сохраняется `access_token`;
- сохраняется ID первой доступной школы;
- возвращаются данные пользователя;
- приложение получает роли и список доступных классов.

Для защищённых запросов используется заголовок:

```http
Authorization: Bearer <JWT>
```

### Обработка ошибок

`ApiService`:
- проверяет HTTP status code;
- преобразует JSON в доменные модели;
- записывает ошибки в лог;
- повторно выбрасывает исключение для обработки на уровне экрана.

При добавлении новых методов сохраняй единый подход к заголовкам, проверке ответа и логированию.

### Настройка адреса backend

В текущей реализации `baseUrl` задан непосредственно в `api_service.dart`.

Это означает:
- локальная сборка frontend по умолчанию обращается к указанному серверу;
- Docker-контейнер Mini App сам по себе не переключает адрес API на локальный `api`;
- изменение адреса backend требует изменения исходного кода и пересборки приложения.

Перед добавлением конфигурации через build-time environment необходимо отдельно изменить `ApiService` и проверить работу локального и production окружений.

## 8. MAX WebApp

### `web/index.html`

Web entrypoint Flutter.

В HTML подключается SDK MAX:

```html
<script src="https://st.max.ru/js/max-web-app.js"></script>
```

Также запускается Flutter bootstrap:

```html
<script src="flutter_bootstrap.js" async></script>
```

MAX SDK необходим для получения данных Mini App, в том числе `initData`.

### `flutter_max_miniapp`

Пакет используется в `main.dart`:

```dart
import 'package:flutter_max_miniapp/flutter_max_miniapp.dart';
```

Инициализация выполняется через:

```dart
final webApp = MaxWebApp();
webApp.init();
```

Полученные данные используются для авторизации на backend.

При проверке приложения вне MAX отсутствие `initData` является ожидаемым поведением.

## 12. Docker Mini App

Сборка и запуск Mini App через Docker Compose описаны в корневом [README.md](../README.md).

В frontend используются:

- `Dockerfile.mini-app` — многоэтапная сборка Flutter Web;
- `nginx.conf` — раздача собранных файлов и fallback на `index.html`.

Сборка выполняется в Flutter SDK image. Готовые файлы копируются в Nginx image.

Сборка только frontend:

```bash
docker compose --env-file backend/.env build mini-app
```

Запуск:

```bash
docker compose --env-file backend/.env up -d mini-app
```

Логи:

```bash
docker compose --env-file backend/.env logs -f mini-app
```

Проверка:

```bash
curl -I http://localhost:8080
```

## 14. Рекомендации по разработке

1. Сетевые запросы размещай в `data/api_service.dart`, а не внутри UI-компонентов.
2. JSON преобразуй в доменные модели.
3. Экраны размещай в `presentation/screens/`.
4. Переиспользуемые виджеты размещай в `presentation/uikit/`.
5. Общие цвета и стили выноси в отдельные файлы.
6. При добавлении API-метода проверяй HTTP-ошибки и формат ответа.
7. Не считай скрытие элемента интерфейса полноценной проверкой прав доступа — backend обязан проверять разрешения самостоятельно.
8. Не добавляй в frontend секреты MAX, JWT или AI-провайдеров.
9. Не сохраняй персональные ответы учеников в клиентских логах.
10. После изменения `pubspec.yaml` обновляй `pubspec.lock`.
11. После изменения frontend пересобирай Web-сборку и Docker-образ Mini App.
12. Проверяй приложение как в браузере, так и внутри MAX Mini App.
